# 校园活动管理平台核心功能代码

本项目实现 PRD V1.1 的 F01–F06，提供 Vue 3 与 TypeScript 页面、Spring Boot REST API、数据库迁移、业务集成测试及可直接运行的 JAR。活动由社团负责人提审，团委老师审核通过后发布，学生报名与取消，负责人按名单签到，系统管理员维护管理权限。

## 在 Windows 11 上演示

安装 Java 21，解压整个代码包，双击 `run-demo.bat`。看到 Started Application 后，在浏览器打开 http://localhost:8080 。关闭运行窗口即可停止。也可在解压目录执行以下命令。

```powershell
java -Duser.timezone=UTC -jar release/campus-activity.jar
```

可执行包包含已构建的前端和后端依赖。演示数据库为 H2 文件数据库，首次启动自动迁移和生成测试账号，数据保存在运行目录的 `data/`。再次运行会保留数据。Linux 和 macOS 可使用 `sh run-demo.sh`。

| 账号 ID | 身份 | 管理范围 |
| --- | --- | --- |
| 1 | 演示学生甲 | 本人报名，完整演示学号 DEMO0001 |
| 2 | 演示学生乙 | 本人报名，完整演示学号 DEMO0002 |
| 3 | 社团负责人 | 读书社，社团 ID 1 |
| 4 | 团委老师 | 读书社审核 |
| 5 | 系统管理员 | 角色授权 |
| 6 | 其他社团负责人 | 科技社，社团 ID 2 |

## 操作演示

1. 选择社团负责人进入“社团活动”，填写草稿并保存，随后提交审核。默认时间在当前时间之后，开始前 30 分钟即可签到。
2. 退出后选择团委老师，在“活动审核”查看活动详情。退回时填写理由，负责人可查看意见、修改并重新提审。通过后活动出现在学生列表。
3. 使用学生甲报名，在“我的报名”查看结果。截止前取消会返还名额，重新报名产生新记录，原取消记录仍保留。
4. 以负责人查看报名名单，按姓名或完整演示学号搜索，点击“确认到场”。学生可查看签到时间。
5. 以负责人取消已发布活动，学生历史记录显示活动已取消。
6. 以系统管理员查询账号 ID 3，撤销其社团负责人授权。原有会话下一次管理请求会被拒绝。

## 技术结构与约定

前端为 Vue 3、TypeScript、Vite，后端为 Java 21、Spring Boot 3.5.8、Spring JDBC。MySQL 8.4 配置及 Docker Compose 位于根目录。H2 的 MySQL 兼容模式用于本地课程演示，MySQL 是原架构方案中的部署数据库。

`backend/src/main/resources/db/migration/V1__schema.sql` 定义账号、社团、分类、活动、提审、审核、报名、授权、会话、幂等记录和审计表。报名采用活动行锁与短事务，扣减名额和新建报名同事务提交。生成列唯一索引限制每人每场一条有效报名，同时保留多次取消记录。审核按提审轮次保留，角色和社团范围在每次管理请求中检查。

接口前缀为 `/api/v1`，认证使用 Bearer 令牌。写接口要求 `Idempotency-Key`，同账号、方法、路径及操作键对应的成功结果与业务事务一起持久化。同键不同内容返回 409。编辑草稿还需 `If-Match`，值来自活动详情的 ETag。所有对外 ID 使用字符串。

数据库列表采用 LIMIT/OFFSET 分页，默认每页 20 条，上限 100 条。活动时间、我的报名、名单和待审列表建立复合索引。标题按包含关键词查询。查询参数使用 JDBC 占位符。学号演示数据只存末四位和带密钥的检索摘要，完整学号不落库。

## 从源码构建

准备 Java 21、Maven 3.9 和 Node.js 22，然后执行以下命令。前端 `dist` 复制到后端静态目录后，JAR 可同时提供网页和 API。Maven 使用 Eclipse Java 编译器以支持本运行环境中的 Java 21。

```sh
cd frontend
npm ci
npm run build
cd ../backend
# 将 ../frontend/dist 内全部文件复制到 src/main/resources/static
mvn test
mvn package
java -Duser.timezone=UTC -jar target/campus-activity-1.0.0.jar
```

前后端分开开发时，后端启动在 8080，前端 `npm run dev` 启动在 5173，Vite 会将 `/api` 代理到后端。

## 使用 MySQL

安装并启动 Docker Desktop，在项目根目录运行以下命令。

```sh
docker compose up --build
```

网页地址为 http://localhost:8080 。Compose 启动 MySQL、应用及 Nginx，并将数据库保存到命名卷。此配置用于本机课程演示，默认密码写在 Compose 中，可通过 `DB_PASSWORD` 与 `DB_ROOT_PASSWORD` 环境变量更改。

已有 MySQL 时，创建 `campus` 数据库并为应用账号授予建表及业务读写权限，然后设置 `SPRING_PROFILES_ACTIVE=mysql`、`DB_URL`、`DB_USER`、`DB_PASSWORD`、`DEMO_LOGIN=true` 后运行 JAR。Flyway 自动建表并加载课程账号。

校内统一认证尚需对接。当前演示入口允许选择测试账号，并在数据库保存随机令牌摘要及 8 小时有效期。正式认证部署应关闭演示入口，并由校内认证适配器签发会话。`STUDENT_SEARCH_KEY` 用于配置学号检索密钥，课程数据使用内置演示密钥。

## 验证范围

已完成前端 TypeScript 检查及生产构建，后端构建与启动，以及基于真实 HTTP 请求和 H2 事务的四项集成测试，测试源码位于 `backend/src/test/java/campus/CoreFlowTest.java`。

| 测试 | 主要断言 |
| --- | --- |
| 发布报名取消签到流程 | 未发布不可见、报名幂等、取消只返还一次、重报保留历史、重复签到保留首次时间、活动取消阻断后续报名 |
| 最后一席并发 | 两个不同学生并发，仅一个成功，另一请求返回满额，报名数与计数一致 |
| 撤销角色 | 旧会话的后续管理请求返回 403 |
| 校验和权限 | 学生不能审核、退回理由必填、同幂等键不同内容冲突、分页越界返回 400 |

浏览器自动化因运行环境禁止 Chromium 所需的本地 socket 而未完成，网页已通过类型检查与生产构建，交互仍需打开演示程序复核。

MySQL 与 Docker 启动流程提供了配置，尚未在本运行环境执行。H2 测试覆盖核心业务逻辑，MySQL 锁等待与索引性能仍需在部署环境验收。PRD 的 300 人在线、30 次提交每秒及架构评审 P95 指标属于后续压测目标。

当前实现采用单实例写入并发预算 16，超过预算返回 429。数据库锁冲突最多重试两次并随机退避。多实例入口限流、HTTPS 证书、统一认证及大规模性能调优需要结合部署环境完成。F07 名单导出和 F08 消息提醒属于 PRD 后续迭代范围。
